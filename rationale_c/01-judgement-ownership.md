# 1. 판단을 누가 하는가 — 가장 큰 결정

## 1-1. LLM에 판정을 맡기지 않고, 규칙이 판정하고 LLM은 문장만 쓴다

**문제.** Trait(협동심·이타심 등) 판정과 학과 매핑을 무엇으로 할 것인가.

**선택지.**

| 방식 | 문제점 |
|---|---|
| 사전에 전부 사람이 정의 | 15 Context × 12 Trait × 학과 수천 개를 미리 정의할 수 없다 |
| LLM이 "비슷하다"로 판정 | 같은 입력에 다른 답이 나오고, 왜 그렇게 판정했는지 설명이 사후 창작이 된다 |
| Agent가 판정 | Agent도 결국 판단 기준이 필요하다. 기준 없는 Agent는 LLM과 같다 |
| 기준을 명시하고 규칙이 판정 | 기준을 사람이 만들어야 한다 |

**결정.** **기준은 사람이 만들고, 판정은 규칙이 하고, LLM은 그 결과를 자연스러운 문장으로
바꾸는 데만 쓴다.**

**근거.** 어떤 방식을 택하든 "무엇을 근거로 그렇게 판단했는가"에 답해야 한다. 그 답을 만드는
주체는 결국 사람이다. 기준이 이미 있다면 그 기준을 규칙으로 쓰는 쪽이 (a) 같은 입력에 같은
결과가 나오고 (b) 근거를 사후 창작이 아니라 실행 기록으로 남길 수 있고 (c) 틀렸을 때 어디를
고쳐야 하는지가 한 곳으로 특정된다. LLM을 넣어도 기준 작성 비용은 그대로 남으면서 위 셋을
잃는다.

코드에 나타난 모습:

- `canonical_mapper` — Exact/Alias 규칙이 먼저, LLM은 마지막 단계이고 그 결과조차 확정이 아니다
- `admission_filter` — 비교 가능성을 네 축의 문자열 일치로 판정한다. 유사도 판단 없음
- Evidence 집계 — 선택 횟수를 세는 산술이다 (A 소유 `evidence_engine`)

**재검토 조건.** Trait가 30개를 넘어 사람이 Mapping을 유지하기 어려워질 때. 그때도 LLM은
후보 생성까지만 하고 확정은 사람이 한다.

## 1-2. 자동 확정은 Exact/Alias에서만. Embedding·LLM 결과는 항상 REVIEW_REQUIRED

**문제.** `전기공학과`, `전기`, `전기전자공학`이 따로 등록돼 있다. 자동으로 합칠 것인가.

**결정.** Alias 표에 **적혀 있는** 표기만 자동으로 합친다. 표에 없으면 임베딩으로 후보 순위만
뽑아 `REVIEW_REQUIRED`로 남긴다. `CONFIRMED`로 가는 길은 사람이 부르는 `confirm()`뿐이다.

**근거.** 실제로 돌려 본 결과:

```
전기공학과      AUTO_MAPPED      electrical_engineering
                근거: 매칭 키 '전기공학'가 label/alias와 정확히 일치
전기전자공학부   AUTO_MAPPED      electrical_engineering
                근거: 매칭 키 '전기전자공학'가 label/alias와 정확히 일치
전자공학과      REVIEW_REQUIRED  후보 순위: electrical_engineering > education > ...
                근거: Exact·Alias 매칭 실패. 임베딩은 순위만 뽑았고 확정 근거로 쓰지 않는다
```

`전자공학과`는 이름이 `전기전자공학`과 겹치지만 **다른 학과**다. 유사도로 합치면 조용히
틀린다. 표에 적힌 것만 합치면, 합친 이유가 항상 "표의 이 줄"로 특정된다.

`AUTO_MAPPED`가 아닌 학과는 `Department.canonical_major_id`를 비워 둔다. 그래서 전공 필터
검색에 미확정 학과가 섞이지 않는다 (`test_unmapped_department_never_matches_canonical_major_filter`).

**재검토 조건.** 전국 수집 후 `REVIEW_REQUIRED` 비율이 30%를 넘으면 Alias 표 확충이 먼저다.
문턱을 낮춰 자동 확정률을 올리는 방향은 택하지 않는다.

## 1-3. 매칭 키를 하나만 만들지 않고 여러 개를 만들어 긴 것부터 대조한다

**문제.** `컴퓨터공학부`에서 조직 접미를 떼야 `컴퓨터공학`과 만난다. 그런데 `학부`를 떼면
`컴퓨터공`이 되고, 실제로 떼야 할 건 `부`다. 어느 쪽이 맞는지는 표기마다 다르다.

**결정.** 뗄 수 있는 후보를 전부 만들어 두고 **긴 키부터** 대조한다.

```
컴퓨터공학부 → ['컴퓨터공학부', '컴퓨터공학', '컴퓨터공']
```

**근거.** 접미 하나만 떼는 규칙은 반드시 어느 한쪽에서 틀린다. 후보를 다 만들고 긴 키가 먼저
걸리게 하면, `컴퓨터공` 같은 짧은 조각이 우연히 다른 전공에 걸리는 사고를 긴 키가 막는다.
이 규칙 하나로 실제 데이터 30개 중 자동 매핑이 22개 → 29개로 늘었다.
