# 개선방안과 기대효과 — 시행착오, 성능지표, 소수학과 확장 비용

이 문서는 발표의 **개선방안·기대효과 페이지**에 바로 옮길 수 있도록 작성했다. 이미 개선해
실측한 결과와 앞으로 투자해야 얻을 수 있는 결과를 구분한다. 여기서 `성능`은 하나의 숫자가
아니라 데이터 누락·오분류·검색 실패·사람 검수량처럼 C가 실제로 측정할 수 있는 지표다.

## 1. 어떤 시행착오를 겪었고 무엇이 좋아졌나

| 시행착오 | 처음 방식의 문제 | 적용한 개선 | 확인된 효과 |
|---|---|---|---|
| 4년제만 포함 | 약학·의학·건축처럼 5~7년 일반과정이 빠짐 | 공식 수업연한 코드로 4~7년 학사과정을 포함 | 6년제 약학 일반과정이 보존되고, 4년 계약학과는 별도 정책으로 제외됨 |
| 수집 단계에서 불필요 행 삭제 | 정책이 바뀌면 원본을 다시 받아야 하고 제외 이유를 설명하기 어려움 | Raw는 보존하고 정규화·추천 범위를 별도 판정 | 일반·계약 과정과 폐지 이력을 Lineage에서 유지하면서 추천 노출만 통제 |
| 학과명·재학생 수로 대표 행 선택 | 신설 학과는 재학생 0명이고 동명 과정도 실제로는 별개일 수 있음 | 공식 `schlMjrId`, 학과특성, 수업연한을 근거로 관계 검수 | 추천 후보 중 중복 `department_id` 0건, 자동 승인 0건 |
| 주간·야간을 같은 후보로 검수 | 중복 588건 대부분이 동일 정책 판단의 반복이었음 | 야간·원격 과정을 추천 범위 밖으로 분리하되 원본은 보존 | 중복 검수 대상이 588그룹에서 16그룹, 계약학과 적용 후 관계 패킷 6그룹으로 축소 |
| N.C.E를 하나의 전공처럼 취급 | `분류 없음`을 실제 학문 분야로 오해해 잘못된 추천 후보가 생김 | N.C.E를 Sentinel로 고정하고 별도 Queue로 분리 | N.C.E 1,901건을 강제 매핑하지 않고 사람 검토 대상으로 보존 |
| 이름에 디자인·미디어·융합이 있으면 자동 분류 | 같은 이름이라도 공식 소계열과 교육과정이 달라 오분류 가능 | 명칭은 검토 신호로만 쓰고 공식 분류가 부족하면 REVIEW | 분류 REVIEW 1,936건을 자동 승인하지 않고 원인별로 분리 |
| URL 도메인만 보고 학과 홈페이지로 인정 | 대학 연구실·미디어센터·다른 학과 URL도 공식 도메인일 수 있음 | 학과 단위·단과대 단위·오연결을 직접 구분 | 실제 오연결 후보 3건이 학생 링크로 노출되는 것을 방지 |
| RAG 검색 성공만 확인 | 근거가 없는데 아무 문서나 반환하는 실패를 놓침 | 근거 있는 질의와 `근거 없음` 질의를 분리 | 현재 smoke fixture에서 positive Recall@5 1.0, 근거 없음 정답률 1.0; 단 4질의 표본임을 명시 |
| 3,837건 Queue를 한 목록으로 전달 | 검토자가 같은 정책을 반복 판단하고 중요한 경계를 늦게 봄 | 반복 규모·교차 Queue·공식 근거 준비도로 작업 우선순위 초안 생성 | 승인 상태를 바꾸지 않고 검토 순서를 재현 가능하게 만듦 |

핵심은 “LLM이 더 잘 판단하게 했다”가 아니다. **틀릴 가능성이 큰 자동 판단을 줄이고, 판단
근거·실패 위치·사람이 볼 순서를 명시해 운영 성능을 높였다.** 이 효과는 추천 적중률이 아니라
중복 0건, 자동 승인 0건, Queue 규모와 재생성 Hash 같은 값으로 검증된다.

## 2. 지금 얻는 기대효과

### 학생 관점

- 계약학과·야간·원격 과정이 일반 주간 학과처럼 섞여 노출될 위험이 줄어든다.
- 약학 6년제처럼 일반적이지 않은 수업연한도 누락되지 않는다.
- 근거 문서가 없으면 비슷한 다른 학과 문서를 대신 보여주지 않고 `근거 없음`으로 멈출 수 있다.
- 추천 결과에 공식 분류·교육과정·출처를 연결할 수 있어 “왜 이 학과인가”를 확인하기 쉬워진다.

### 운영자·개발자 관점

- 같은 입력에서 같은 Queue와 보고서가 생성되어 문제를 다시 재현할 수 있다.
- 자동 분류와 사람 검토의 경계가 분명해져 잘못된 자동 승격을 막는다.
- 3,837건을 원인·파급력 순으로 묶어 검수자가 같은 판단을 반복하는 비용을 줄인다.
- Alias 충돌, 짧은 Alias, RAG 오검색을 정상 감사 항목으로 다뤄 조용히 누적되는 오류를 찾는다.
- Raw·Lineage와 추천 노출을 분리했기 때문에 정책 변경 시 원본 재수집 없이 다시 생성할 수 있다.

## 3. 소수학과까지 포함하려면 어떻게 개선하나

소수학과 확장은 학과 이름을 Alias에 많이 추가하는 방식으로 해결하면 안 된다. 호텔경영·해양·
국방처럼 이름이 비슷해도 진로와 교육과정이 다른 분야가 있기 때문이다. 다음 네 단계로 진행한다.

### 3-1. 데이터 커버리지부터 확인

전국 `classification_results.jsonl`에서 관광·호텔, 농업, 해양, 국방, 특수교육, 종교 등
관심 분야별로 다음을 집계한다.

- 현재 상태 학과 수와 지역·대학 분포
- 추천 후보, REVIEW, N.C.E, 추천 범위 제외 비율
- 공식 소계열이 기존 전공군에 연결되는지
- 특정 분야가 REVIEW/N.C.E에 몰려 추천 후보에서 사라지는지

이 단계는 LLM 호출이 필요 없다. 전국 입력이 준비되면 기존 결정론적 생성기에 집계 규칙과 테스트를
추가하면 된다.

### 3-2. 대표 학과의 공식 근거를 표본 수집

각 분야에서 수도권·지역, 종합대·특성화대가 섞이도록 5~10개 학과를 고른다. 학과별로 최소
`학과 소개 + 교육과정` 두 종류를 수집하고, 가능하면 졸업요건과 진로 안내를 추가한다.

URL은 공식 대학 도메인이라는 이유만으로 승인하지 않는다. 학과 페이지인지, 단과대 페이지인지,
연구실·홍보센터 같은 오연결인지 함께 기록한다. 공식 문서를 찾지 못한 학과도 제외하지 않고
`source_missing` 사례로 평가 세트에 남긴다.

### 3-3. 소수학과 전용 실패 테스트를 만든다

분야마다 다음 질의를 최소 한 개씩 둔다.

- 정답 문서를 찾아야 하는 교육과정 질의
- 비슷한 다른 학과 문서를 고르면 실패하는 교란 질의
- 자료가 없어서 빈 결과가 정답인 질의
- 호텔경영/관광경영, 해양공학/수산학처럼 경계가 가까운 비교 질의

평가는 `Recall@3/5`, 근거 없음 정답률, 잘못된 대학·학과 출처 반환률로 나눈다. 검색 결과가
나왔다는 사실만 성공으로 세지 않는다.

### 3-4. 포함 여부를 단계적으로 결정

한 번에 전국 모든 소수학과를 공개하지 않고 아래 Gate를 통과한 분야부터 포함한다.

1. 공식 소계열 또는 공식 교육과정 근거가 있다.
2. 대표 학과 평가에서 잘못된 학과 출처 반환이 없다.
3. `source_missing`을 다른 문서로 대체하지 않는다.
4. REVIEW/N.C.E 행을 사람이 확인했으며 승인자를 기록한다.
5. 포함 전후 추천 후보 수와 오류 사례가 Manifest에 남는다.

## 4. 규모와 비용 — 선택 가능한 세 가지 안

아래 수치는 **의사결정을 위한 작업량 추정치**다. 현재 저장소 구조, 학과당 공식 문서 2건,
문서 확인 5~10분, 자동 수집·정규화가 동작한다는 가정으로 계산했다. 외부 유료 모델 단가는
계약마다 달라 원화로 고정하지 않고 호출량과 문서량을 제시한다.

| 안 | 대상 규모 | 예상 작업 | 사람 작업량 | 저장·호출 규모 | 적합한 목적 |
|---|---:|---|---:|---:|---|
| A. 커버리지 진단만 | 6~8개 소수 분야, 전국 행 집계 | 분야별 후보/REVIEW/N.C.E 분포와 누락 원인 확인 | 0.5~1인일 | LLM 0회, 추가 저장 수 MB 이하 | 포함할 분야를 먼저 고를 때 |
| B. 권장 Pilot | 6~8개 분야 × 5~10학과 = 30~80학과 | 공식 문서 60~160건, 질의 30~80건, 오연결 검수 | 2~4인일 | 원문·Chunk 약 10~100MB, Embedding 1회/Chunk | 발표 근거와 실제 포함 가능성을 함께 확인할 때 |
| C. 전국 Long-tail | 소수 분야 1,000~3,000학과 | 공식 문서 2,000~6,000건 수집·갱신·실패 재처리 | 자동화 개발 5~10인일 + 초기 검수 10~30인일 | 원문 수백 MB~수 GB, 수천~수만 Chunk Embedding | 운영 서비스에서 전국 세부학과를 지속 지원할 때 |

비용은 다음 식으로 다시 계산할 수 있다.

```text
사람 검수 시간 = 문서 수 × 문서당 5~10분 + 실패 URL 재탐색 시간
Embedding 비용 = 전체 Chunk 입력 token ÷ 1,000,000 × 사용 모델의 1M token 단가
LLM 판정 비용 = 평가 질의 수 × 질의당 입출력 token × 사용 모델 단가
유지 비용 = 학기/연도 갱신 문서 수 × 재수집·재검수 시간
```

분류와 커버리지 집계에는 LLM이 필요하지 않다. LLM은 공식 근거를 대신 판정하는 용도가 아니라
질의 다양화나 검토 보조에만 선택적으로 쓴다. 따라서 A안은 API 비용 없이 바로 실행할 수 있고,
B안도 Embedding을 로컬 결정론적 방식으로 유지하면 외부 API 비용을 0으로 둘 수 있다.

## 5. 어떤 안을 선택하는 것이 좋은가

### 현재 발표와 MVP가 목적이면: A + 작은 B

먼저 A안으로 6~8개 분야의 실제 데이터 누락 위치를 찾고, 호텔경영을 포함한 3개 분야에서
학과 5개씩만 B안 Pilot을 수행한다. 약 **15학과·공식 문서 30건·평가 질의 15~30건**, 사람
작업은 **1~2인일** 수준이다. “소수학과도 된다”는 막연한 주장이 아니라 구체적인 실패 사례와
검색 지표를 발표할 수 있다.

### 실제 공개 범위를 넓히는 것이 목적이면: B 완료 후 분야별 Gate

6~8개 분야 전체 Pilot 결과를 비교해 잘못된 출처 반환률이 낮고 공식 근거 확보율이 높은 분야부터
공개한다. 근거 확보가 어려운 분야는 학과를 삭제하지 않고 검색·추천 노출만 보류한다. 이렇게 하면
전국 Long-tail 비용을 한 번에 부담하지 않고도 포함 범위를 점진적으로 넓힐 수 있다.

### C안은 지금 바로 권장하지 않음

전국 수천 학과의 홈페이지 구조는 서로 달라 최초 수집보다 갱신·오연결 검수가 더 비싸다. Pilot에서
분야별 근거 확보율과 URL 실패율을 측정한 뒤, 자동 수집 성공률이 충분한 분야에만 C안을 적용하는
편이 낫다.

## 6. 발표용 한 장 요약

**개선방안**

- 공식 코드·과정 특성으로 포함 범위를 나누고 Raw/Lineage는 보존한다.
- N.C.E·융합·디자인·미디어 경계를 자동 확정하지 않고 실패 유형과 검수 순서를 만든다.
- 검색은 “찾음”뿐 아니라 “근거가 없을 때 비움”과 잘못된 학과 출처를 함께 평가한다.
- 소수학과는 6~8개 분야 커버리지 진단 → 30~80학과 Pilot → Gate 통과 분야 공개 순으로 확장한다.

**기대효과**

- 일반과정 누락과 계약·야간 과정 오노출을 동시에 줄인다.
- 중복 후보와 근거 없는 자동 분류를 막아 추천 데이터의 신뢰성과 설명 가능성을 높인다.
- 검수 대상을 정책 단위로 묶어 운영 비용을 낮추고, 같은 입력에서 결과를 재현할 수 있다.
- 작은 Pilot 비용으로 소수학과 포함 가능성을 먼저 확인해 전국 확장의 낭비를 줄인다.

**권장 의사결정**

> 우선 15학과·문서 30건 규모의 소수학과 Pilot을 1~2인일로 수행한다. 결과가 좋은 분야만
> 30~80학과 규모로 확장하고, 공식 근거 확보율과 오출처율을 본 뒤 전국 확대 여부를 결정한다.
