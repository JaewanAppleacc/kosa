# A 승인 대기 — 변경안 2건 (승인하면 바로 적용 가능)

작성 2026-08-24 · 브랜치 `worker-c`

**A가 소유한 파일이라 C가 고치지 않았다.** 대신 **변경 내용·영향·검증까지 미리 만들어

C가 판단해도 되는 나머지 3건은 §3에서 이미 결정하고 근거를 남겼다. A가 다시 볼 필요 없다.

## 1. `src/ids.py` — `generate_department_id()`에 주야간 추가

### 무엇이 문제인가

중복 588건의 원인을 갈랐더니 한쪽으로 쏠렸다.

```
주야간이 갈림    573  (97.4%)
학과 상태 이력   112
수업연한           2
차이 없음         12
```

현재 규칙은 `(schl_id, 학과명, 단과대학)` 셋만 쓴다. 그래서 같은 대학·같은 학과명의
**주간 과정과 야간 과정이 같은 `department_id`를 받는다.** 대학알리미는 이 둘을 별도
`schlMjrId`로 관리하는 서로 다른 편제단위다.

**데이터 문제가 아니라 id 규칙 문제다.**

### 실측 시뮬레이션 (ids.py를 고치지 않고 계산)

주야간을 해시에 넣었을 때 무엇이 달라지는지 25,389건 전체로 돌려봤다.

| | 현재 | 주야간 추가 시 |
|---|---|---|
| 중복 그룹 | **588** | **22** |
| 해소되는 그룹 | — | **566** |

검토 대기 588건 중 **566건이 사라진다.** 남는 22건은 주야간과 무관한 실제 중복이라
어차피 사람이 봐야 한다.

### 대가 — Master 재생성

| 영향 | 규모 |
|---|---|
| 기존 Master `department_id` 변경 | **35건 전부** |
| canonical 매핑 재검수 | **35건** |
| 시연 데이터 중 주야간 값이 있는 행 | **0건** |

마지막 줄이 중요하다. **현재 시연 35건에는 주야간 값이 아예 없다**(`data/raw/
departments.raw.jsonl`에 그 필드가 없다). 즉 주야간을 해시에 넣어도 **35건의 실질 내용은
안 바뀌고 id 문자열만 달라진다.** 매핑 34건은 학과명 기준이라 재적용하면 같은 결과가 나온다.

### 변경안

```python
# src/ids.py
def generate_department_id(
    schl_id: str, department_name: str, college_name: str, day_night: str = ""
) -> str:
    """조사년도(svyYr)는 의도적으로 제외한다 — C 질문 2번 결정 사항.

    주야간을 넣는 이유: 대학알리미는 같은 학과의 주간/야간 과정을 별도 편제단위
    (schlMjrId)로 관리한다. 넣지 않으면 둘이 같은 id를 받아 전국 규모에서 566건이
    중복으로 잡힌다(2026-08-24 실측). 기본값 ""이라 기존 호출부는 그대로 동작한다.
    """
    return f"dept_{_sha256_prefix(schl_id, department_name, college_name, day_night)}"
```

**기본값 `""`로 두면 기존 호출부가 안 깨진다.** 시연 빌더(`career_build_department_master.py`)는
인자를 안 넘기므로 현재와 동일한 id를 계속 만든다 — **A가 승인해도 Master는 그대로다.**
전국 정규화기만 주야간을 넘겨 쓰면 된다.

### 승인 시 C가 할 일

```
1. src/ids.py 위 변경 적용
2. scripts/career_normalize_academyinfo.py에서 day_night 전달
3. 정규화·분류·Queue 재생성
4. 중복 588 → 22 확인, 테스트 갱신
```

**반려 시:** 588건을 사람이 그대로 검토한다. 그중 449건은 "주야간만 갈리는" 묶음이라
정책 하나로 일괄 처리는 가능하다(§4 참조).

## 2. `src/schemas/major.py` — `department_url` 공개

A 결정 §5에서 이미 정책은 확정됐다(`scope == "department"`만 공개, `college` 3건은 `None`).
남은 것은 **공개 Schema에 필드가 열려 있는지**뿐이다.

A 결정 문서는 "기존 A의 `Department.department_url` Schema를 그대로 재사용한다"고 적었지만,
**worker-c의 `src/schemas/major.py`에는 이 필드가 없다.** A의
`integration/academyinfo-pipeline` 브랜치에만 있는 것으로 보인다.

```
worker-c  src/schemas/major.py  →  department_url 없음 (확인함)
```

### 필요한 것

두 브랜치 중 어느 쪽이 정본인지 확정하고, worker-c 기준으로 병합되면 C가 빌더 배선을 넣는다.
값 37건은 이미 `data/raw/departments.raw.jsonl`에 `department_url` ·
`department_url_scope` · `department_url_note`로 보존돼 있다.

**이게 열리기 전까지 B의 프론트 작업(`worker-b-department-source-url.md`)은 시작해도
화면에 값이 안 내려온다.** 순서가 있다.

## 3. C가 판단해 처리한 것 — A는 확인만 (재판단 불필요)

앞선 보고에서 "A 판단 필요"로 올렸던 것 중 **C 작업 범위에 속하는 것**을 결정하고 근거를
남겼다. 이의가 없으면 그대로 간다.

### 3-1. HTTP만 지원하는 학과 홈페이지 3건 → **공개 후보로 유지**

```
http://cse.hanyang.ac.kr/                                 한양대 컴퓨터소프트웨어학부
http://idesign.hanyang.ac.kr/page/?pid=dep_communication   한양대 커뮤니케이션디자인학과
http://me.pusan.ac.kr/new/main/                            부산대 기계공학부
```

`https://`로 바꾸면 세 곳 다 `ConnectError` — **학교 서버가 HTTPS를 열지 않는다.**
우리가 URL을 잘못 넣은 게 아니다.

**결정: `DEPARTMENT_SCOPE_CONFIRMED`로 둔다.** HTTP라는 이유로 보류하면 그 학과 학생은
홈페이지 링크를 영영 못 본다. 링크가 없는 것보다 HTTP 링크가 낫다.

`findings`에 `"HTTP만 제공 — 해당 학교 서버가 HTTPS를 열지 않음(실측 확인)"`을 기록해,
나중에 학교가 HTTPS를 열면 자동으로 걸러지지 않고 사실이 남아 있게 했다.

**재검토 조건:** 브라우저가 "안전하지 않음"을 표시하는 것이 학생에게 불신을 준다고
판단되면 `None`으로 바꾼다. 그때는 3건만 상태를 바꾸면 된다.

### 3-2. N.C.E ↔ 분류 REVIEW 984건 겹침 → **한 번에 처리**

두 Queue는 축이 다르다("어느 전공군인가" vs "추천해도 되나"). 겹치는 984건은 양쪽에
상호 참조 플래그(`also_in_*`)를 붙여 뒀다.

**결정: 겹치는 984건을 먼저, 한 번에 본다.** 분류 근거(공식 소계열)가 확보되면 적격성
판정도 대부분 따라 정해지기 때문이다. 순서를 반대로 하면 같은 자료를 두 번 찾게 된다.

권장 순서:

```
1. 겹침 984건        분류 근거 확보 → 적격성도 함께 판정
2. N.C.E 나머지 2,673건
3. 분류 REVIEW 나머지 3,470건
```

### 3-3. 검토 인력 배분 → **작업량 추정과 묶음 제공**

인력 배분은 기술 판단이 아니라 사람이 정할 일이다. 대신 **정할 수 있게 재료를 만들었다** —
§4.

## 4. 검토 작업량 — 588건을 3덩이로 줄였다

중복 Queue에 `review_batch`를 붙였다. **판정한 것이 아니라 작업을 정리한 것이다.**
`decision_status`는 전부 `REVIEW_REQUIRED` 그대로다.

| 묶음 | 그룹 수 | 성격 |
|---|---|---|
| `BATCH_DAY_NIGHT_ONLY` | **449** | 주야간을 빼면 모든 필드가 동일. **정책 하나로 일괄 판단 가능** |
| `BATCH_DAY_NIGHT_PLUS` | 124 | 주야간 외에도 갈림. 개별 확인 필요 |
| `INDIVIDUAL` | 15 | 주야간 무관. 원본 직접 확인 |

449건은 "**같은 학과의 주간/야간 과정을 별도 학과로 볼 것인가**"라는 질문 하나로 끝난다.
한 건씩 보면 449번 같은 판단을 반복하게 된다.

**§1이 승인되면 이 449건은 아예 사라진다** — id에 주야간이 들어가면 중복이 아니게 되기
때문이다. 그래서 §1 판단이 검토 작업량을 가장 크게 줄인다.
